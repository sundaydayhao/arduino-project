# Arduino Uno 实现十字路口红绿灯与 3621BH 倒计时

## 1. 目标

本文说明如何在 `Arduino Uno` 上实现与 Mega 版本类似的功能：

- 东、南、西、北四个方向的红黄绿三色灯
- 每个方向一个 `3621BH` 共阳两位数码管，用于倒计时
- 基本两相位交通控制
- 支持后续扩展左转、行人按钮、蜂鸣器

重点区别在于：

- `Arduino Uno` 的 IO 数量明显少于 `Mega 2560`
- 不能再像 Mega 示例那样为每一路灯和每一个数位直接分配独立 IO
- 必须引入 `74HC595`、驱动管和动态扫描

## 2. 为什么 Uno 不能直接照搬 Mega 方案

`Arduino Uno` 可直接使用的常规 IO 资源：

- 数字口 `D0-D13`
- 模拟口 `A0-A5` 也可作为数字口使用

总数大约 `20` 路，但还要考虑：

- 串口下载和调试尽量不要长期占用 `D0/D1`
- 若后续加按键、蜂鸣器、串口模块，IO 会更紧张

而本项目的原始需求如果不做复用：

- 交通灯：`4 方向 x 3 色 = 12 路`
- 倒计时段线：`8 路`
- 4 只 `3621BH` 共 `8` 个数位位选

合计需要：

- `12 + 8 + 8 = 28` 路输出

因此 `Uno` 方案必须采用扩展输出架构。

## 3. 推荐硬件架构

### 3.1 核心方案

推荐以下组合：

- 1 x `Arduino Uno`
- 4 x `74HC595`
- 2 x `ULN2803A`
- 8 x `PNP` 三极管或 `P-MOSFET`
- 4 x `3621BH` 共阳两位数码管
- 4 组交通灯模块或 12 颗 LED
- 外部 `5V` 电源

### 3.2 为什么推荐 4 个 74HC595

`74HC595` 是串入并出移位寄存器，一个芯片提供 `8` 路锁存输出。4 个串联后可以得到 `32` 路输出，而 Arduino 只需要 `3` 根控制线：

- `DATA`
- `CLOCK`
- `LATCH`

这样 Uno 只消耗 3 根 IO，就能统一控制：

- 12 路交通灯
- 8 路数码管段线
- 8 路数码管位选

总共只使用 `28` 个输出位，还剩 4 位空余，可作为后续扩展。

## 5. 驱动电路建议

### 5.1 交通灯驱动

不要让 `74HC595` 直接带交通灯负载，推荐：

- `74HC595 输出 -> ULN2803A 输入`
- `ULN2803A 输出 -> 灯负极`
- `灯正极 -> +5V`

优点：

- 输出电流能力更稳
- 更适合后续换大一点的灯组
- 软件仍然只需要关心逻辑高低

### 5.2 3621BH 段线驱动

`3621BH` 是共阳数码管，段线需要“下拉导通”。

推荐：

- `74HC595 段线输出 -> ULN2803A 输入`
- `ULN2803A 输出 -> 限流电阻 -> 所有数码管对应段脚`

这种接法意味着：

- 某一段要点亮时，逻辑上要让对应 `74HC595` 输出为高
- 经 `ULN2803A` 下拉后，该段导通发光

### 5.3 3621BH 位选驱动

共阳位选需要高边驱动，推荐：

- `74HC595 位选输出 -> PNP 三极管或 P-MOSFET 控制`
- `PNP/P-MOS 输出 -> 3621BH 的 DIG1/DIG2`
- `3621BH 公共阳极 -> +5V`

需要注意：

- 位选逻辑通常会是“低有效”或“经反相后高有效”，取决于你具体的三极管连接方式
- 软件里应把“位选有效电平”做成单独常量，不要写死在业务逻辑里

## 6. Uno 推荐接线

Arduino Uno 只负责控制移位寄存器和少量扩展功能，推荐如下：

| Uno 引脚 | 用途 |
| --- | --- |
| D2 | `74HC595 DATA` |
| D3 | `74HC595 CLOCK` |
| D4 | `74HC595 LATCH` |
| D5 | 蜂鸣器或预留 |
| D6 | 行人按钮或预留 |
| D7 | 调试 LED 或预留 |

其他建议：

- `D0/D1` 保留给串口下载与调试
- `A0-A5` 保留给未来扩展，除非你确定不会再加功能

## 8. 软件框架

Uno 版本的软件建议分成两层。

### 8.1 业务层

业务层与 Mega 版本基本一致，仍然保留：

- `LampColor`
- `Direction`
- `StageDefinition`
- `IntersectionController`

业务层只关心：

- 当前阶段是什么
- 哪个方向亮什么灯
- 每个方向应该显示多少倒计时

### 8.2 硬件抽象层

Uno 版本需要新增两个关键模块：

#### `ShiftRegisterBus`

职责：

- 维护 32 位输出缓冲区
- 通过 `shiftOut()` 或 SPI 把 32 位一次性刷新到 4 个 `74HC595`
- 提供 `setBit(index, value)` 接口

#### `DisplayScanner`

职责：

- 维护 8 个物理数位的显示缓存
- 每次只使能 1 个数位
- 设置对应段码
- 调用 `ShiftRegisterBus.flush()` 输出到移位寄存器

#### `LampDriver`

职责：

- 把 `North/South/East/West` 的红黄绿灯状态映射到 32 位缓冲区中的对应位
- 不直接操作 Arduino 引脚

## 9. 推荐调度方式

### 9.1 主状态机

主状态机继续使用 `millis()`：

- 绿灯 `15s`
- 黄灯 `3s`
- 全红 `2s`

### 9.2 数码管扫描

推荐每 `1ms` 到 `2ms` 扫描一个物理数位：

- 系统共 `8` 个数位
- 每轮完整扫描约 `8ms` 到 `16ms`
- 整体刷新率约 `62.5Hz` 到 `125Hz`

这个范围通常不会肉眼闪烁。

实现方式有两种：

1. 在 `loop()` 中基于 `micros()` 高频轮询
2. 用 `Timer2` 中断定时扫描

对于课程设计，优先推荐第一种：

- 易理解
- 易调试
- 不需要先处理复杂中断共享问题

## 10. 软件执行流程

### 10.1 `setup()`

- 初始化 `ShiftRegisterBus`
- 清空 32 位输出缓冲
- 初始化交通灯控制器
- 初始化显示扫描器
- 设置初始交通相位

### 10.2 `loop()`

- 高频调用 `displayScanner.service()`
- 周期性推进 `IntersectionController`
- 把新的灯状态写入移位寄存器缓冲
- 把新的倒计时拆成 8 个物理数位
- 刷新输出

## 11. 与 Mega 方案的差异

| 项目 | Mega 方案 | Uno 方案 |
| --- | --- | --- |
| IO 分配 | 可大量直连 | 必须扩展输出 |
| 显示驱动 | 可直接单独接线 | 更适合统一扫描 |
| 电路复杂度 | 低 | 中等 |
| 软件复杂度 | 低到中 | 中到高 |
| 成本 | 稍高 | 主控低，但外围器件更多 |

## 12. 风险与注意事项

- `74HC595` 本身不适合直接驱动较大电流负载，必须加驱动级
- 数码管扫描频率过低会闪烁
- 若刷新位选和段码的顺序不对，会出现重影
- 若多个方向同时大电流点亮，外部 `5V` 电源必须稳定
- `Uno` RAM 很小，代码结构要清晰，但不要引入过重的动态内存使用

## 13. 实施建议

推荐按下面顺序推进：

1. 先只接 1 只 `3621BH`，验证段码和位选极性
2. 再扩展到 4 只数码管，验证动态扫描是否稳定
3. 加入 4 个方向三色灯
4. 最后接入完整交通相位状态机

这样排错成本最低。

## 14. 结论

`Arduino Uno` 完全可以实现这个十字路口红绿灯系统，但前提是：

- 不再使用“每个负载独占一个 IO”的做法
- 使用 `74HC595 + ULN2803A + 高边位选驱动`
- 软件上采用“状态机 + 动态扫描 + 输出缓冲”

如果只是为了更快做出演示板，`Mega 2560` 更直接；如果你希望在 `Uno` 上完成更典型的嵌入式资源受限设计，这套方案是合理的。
