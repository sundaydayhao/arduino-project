# Arduino 十字路口红绿灯设计

## 1. 目标

实现一个教学/演示型十字路口控制器，满足以下要求：

- 东、南、西、北四个方向均有红灯、黄灯、绿灯
- 每个方向带两位倒计时显示
- 当前实现优先面向 `3621BH` 共阳型两位数码管
- 采用标准两相位控制：
  - 南北直行同时放行
  - 东西直行同时放行
- 预留后续扩展：
  - 左转相位
  - 行人信号
  - 蜂鸣器
  - 按键或串口配置配时

## 2. 推荐硬件方案

### 2.1 推荐控制板

优先推荐 `Arduino Mega 2560`，原因：

- IO 口充足，适合教学和原型验证
- 四个方向共 12 路灯输出，外加 4 只 `3621BH` 数码管的动态扫描控制，IO 仍然够用
- 后续加按键、蜂鸣器、串口屏更方便

如果必须压缩成本，也可以改成：

- `Arduino Nano/Uno + 74HC595 + 三极管阵列`

但软件和接线复杂度会明显上升。

### 2.2 主要器件

- 1 x `Arduino Mega 2560`
- 12 x 红/黄/绿 LED 或 4 组交通灯模块
- 12 x 限流电阻
  - 单颗 LED 常用 `220 ohm` 到 `330 ohm`
- 4 x `3621BH` 共阳型两位数码管
- 8 x 数码管段限流电阻
  - 共用段线动态扫描时，`a-g + dp` 共 8 路
- 8 x 高边位选驱动
  - 推荐 `PNP` 三极管或 `P-MOSFET`
- 1 x `ULN2803A`
  - 推荐用于数码管段电流下拉
- 1 x `ULN2803A` 或 NPN/MOSFET 驱动级
  - 当灯组电流较大时不要直接由 MCU 引脚驱动
- 1 x `5V` 外部电源
  - 不建议所有灯都只靠 Arduino 板载 USB 供电
- 若干杜邦线、面包板或焊接板

### 2.3 电气注意事项

- `Arduino GND` 与外部 `5V` 电源地必须共地
- 若单路灯电流超过 `20mA`，必须加驱动级
- `3621BH` 是共阳数码管，位选侧要提供高电平电流，段选侧负责下拉导通
- 若使用的是现成交通灯模块，先确认其输入驱动方式
- 如果后续换成 `12V` 灯板，驱动级和供电需要整体调整

## 3. 硬件连接框架

### 3.1 方向定义

- `North` 北
- `South` 南
- `East` 东
- `West` 西

### 3.2 灯输出分配示例

以下分配对应示例程序：

| 方向 | 红灯 | 黄灯 | 绿灯 |
| --- | --- | --- | --- |
| North | D2 | D3 | D4 |
| South | D5 | D6 | D7 |
| East | D8 | D9 | D10 |
| West | D11 | D12 | D13 |

### 3.3 3621BH 引脚定义

下面的引脚定义基于 `XLITX CL3621BH` 数据手册：

| 功能 | 数码管引脚 |
| --- | --- |
| A | 3 |
| B | 9 |
| C | 8 |
| D | 6 |
| E | 7 |
| F | 4 |
| G | 1 |
| DP | 2 |
| DIG1 | 10 |
| DIG2 | 5 |

说明：

- `DIG1`、`DIG2` 是两个数位的公共阳极
- 本方案不使用小数点，`DP` 可以不接或保留
- 不同厂家兼容料号通常一致，但焊接前仍建议对照你手上的数据手册再核一次

### 3.4 倒计时显示连接示例

4 个方向共 4 只 `3621BH`，总共 8 个数位。推荐采用“段线共用、位选独立”的动态扫描方式。

#### 段线连接

8 条段线由 Arduino 统一输出，经 `ULN2803A` 下拉驱动：

| 段 | Arduino | 说明 |
| --- | --- | --- |
| A | D22 | 接所有数码管的 A 段 |
| B | D23 | 接所有数码管的 B 段 |
| C | D24 | 接所有数码管的 C 段 |
| D | D25 | 接所有数码管的 D 段 |
| E | D26 | 接所有数码管的 E 段 |
| F | D27 | 接所有数码管的 F 段 |
| G | D28 | 接所有数码管的 G 段 |
| DP | D29 | 可选 |

#### 位选连接

8 个数位各自独立位选，由高边驱动控制：

| 方向数位 | Arduino |
| --- | --- |
| North 十位 | D30 |
| North 个位 | D31 |
| South 十位 | D32 |
| South 个位 | D33 |
| East 十位 | D34 |
| East 个位 | D35 |
| West 十位 | D36 |
| West 个位 | D37 |

#### 推荐驱动拓扑

共阳数码管不建议直接由 Arduino 同时承担位选供电和段电流下拉，推荐如下连接：

- `Arduino 段线 IO -> ULN2803A 输入`
- `ULN2803A 输出 -> 限流电阻 -> 所有数码管对应段脚`
- `数码管 DIG1/DIG2 -> PNP 三极管或 P-MOSFET -> +5V`
- `Arduino 位选 IO -> 高边驱动控制端`

这样做的好处：

- 段线只占用 8 路 IO，四个方向仍可独立显示不同倒计时
- 动态扫描时任一时刻只点亮 1 个数位，瞬时电流更容易管理
- 软件上只需要维护 8 个物理数位缓冲，后续扩展位数也比较直接

如果使用单颗 LED 演示，可简化为：

- `Arduino IO -> 电阻 -> LED -> GND`

如果使用较大电流灯组，推荐：

- `Arduino IO -> ULN2803A 输入`
- `ULN2803A 输出 -> 灯负极`
- `灯正极 -> +5V`

数码管和交通灯都走驱动级，接法更稳，也更接近实际工程。

## 4. 控制逻辑设计

### 4.1 基本相位

推荐采用 6 个阶段构成一个循环：

1. `NS_GREEN`
   - 南北绿，东西红
2. `NS_YELLOW`
   - 南北黄，东西红
3. `ALL_RED_TO_EW`
   - 全红，准备切换到东西放行
4. `EW_GREEN`
   - 东西绿，南北红
5. `EW_YELLOW`
   - 东西黄，南北红
6. `ALL_RED_TO_NS`
   - 全红，准备切换到南北放行

### 4.2 推荐配时

演示型默认值：

- 绿灯：`15 s`
- 黄灯：`3 s`
- 全红：`2 s`

完整周期：

- `15 + 3 + 2 + 15 + 3 + 2 = 40 s`

### 4.3 倒计时逻辑

建议每个方向显示“当前颜色状态距离下一次变化还剩多少秒”：

- 当前是绿灯：显示距离变黄还剩多少秒
- 当前是黄灯：显示距离变红还剩多少秒
- 当前是红灯：显示距离变为黄/绿前的等待秒数

对于教学系统，这种定义最容易理解，也最适合做统一软件抽象。

## 5. 软件框架

### 5.1 模块划分

建议按下面的职责拆分：

#### `LampColor`

枚举灯状态：

- `RED`
- `YELLOW`
- `GREEN`

#### `Direction`

枚举方向：

- `NORTH`
- `SOUTH`
- `EAST`
- `WEST`

#### `StageDefinition`

定义一个相位阶段：

- 阶段名
- 阶段持续时间
- 南北组灯色
- 东西组灯色

#### `TrafficLightHead`

负责单个方向的三色灯输出：

- 保存 red/yellow/green 三个引脚
- 提供 `setColor()` 接口

#### `CountdownDisplayScanner`

负责 4 只 `3621BH` 的统一动态扫描：

- 维护 8 个物理数位缓冲区
- 把 `00-99` 拆成十位和个位
- 周期性切换当前点亮数位
- 输出段码并控制位选

#### `IntersectionController`

系统核心控制器：

- 保存阶段表
- 维护当前阶段索引
- 计算当前阶段剩余秒数
- 计算每个方向倒计时
- 驱动四个方向灯并更新四组倒计时缓冲

### 5.2 核心设计原则

- 不要在 `loop()` 里用长时间 `delay()` 堵塞
- 使用 `millis()` 做交通状态机计时
- 使用 `micros()` 或定时器中断做数码管动态扫描
- 所有交通逻辑由“状态机”统一管理
- 所有硬件输出都通过抽象层调用，不要把业务逻辑散在各处
- `loop()` 中不能出现长时间 `delay()`，否则数码管会明显闪烁

### 5.3 软件调用链

建议流程如下：

1. `setup()`
   - 初始化灯引脚
   - 初始化数码管段线和位选
   - 设置初始阶段
2. `loop()`
   - 高频调用数码管扫描服务
   - 根据 `millis()` 判断是否到达下一秒
   - 若需要，推进相位
   - 刷新灯状态
   - 更新四个方向倒计时缓冲

## 6. 扩展建议

### 6.1 加左转相位

可以把阶段表改成：

- 南北左转
- 南北直行
- 南北黄
- 全红
- 东西左转
- 东西直行
- 东西黄
- 全红

软件框架本身不需要推翻，只要扩展阶段表即可。

### 6.2 加行人按钮

增加：

- 按键输入采集
- 行人请求标志位
- 仅在下一个安全窗口插入行人相位

### 6.3 加串口配置

可通过串口命令动态修改：

- 绿灯时长
- 黄灯时长
- 全红时长
- 显示亮度

## 9. 适用边界

本方案适合：

- Arduino 课程设计
- 电子制作演示
- 面包板原型验证

本方案不适合直接上路实用。真实交通信号机还需要考虑：

- 冗余与故障安全
- 冲突检测
- 断电恢复
- 防雷与 EMC
- 工业级供电与隔离
- 法规与检测认证
